The Zig flat codec previously rejected typed arrays and DataView. It now supports all twelve typed-array kinds, including Float16Array, and DataView against devalue 5.9.4, preserving view identity, shared backing buffers, offsets, lengths and exact raw bytes. The public graph API provides metadata-only views and a visible-byte copying constructor that matches upstream Node Buffer normalization. Ordinary subviews serialize the whole backing buffer, as upstream does.

The decoder checks the raw ArrayBuffer slot before hydration, then requires a genuine buffer after revival. Bounds validation avoids overflow and allocation from claimed lengths. Existing reducer/reviver precedence is preserved; strict malformed-bound/arity acceptance differences remain documented. Go runtime APIs are unchanged: their binary views remain expression-only, so this adds Zig parity against upstream without claiming Go flat-view support or full devalue feature parity.

Validation: `just test` and `just lint` pass; 33 native tests pass in Debug and ReleaseSafe. Tests include 109 JS-recorded binary inputs with independent encoder construction, decoded contents and handle topology; per-kind malformed/revived-buffer matrices, ownership/growth, allocation failures and corpus mutations. A fresh public Zig consumer matches independently constructed pinned-JS bytes. Both Go modules match 108 standalone backing-buffer documents and demonstrate their existing flat-view rejection.
